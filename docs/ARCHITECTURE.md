# Cache and rendering architecture

## Current prototype

`ChunkProviderClientMixin` captures a detached `Chunk` when the client provider unloads a live chunk. Before Minecraft replaces or disconnects its world, `MinecraftMixin` captures remaining live chunks while the old world identity is still active. It drains previous saves, then captures and drains batches of 512 so the 1024-entry pending queue cannot overflow during this operation. Normal shutdown also passes through this world-replacement path. Section block palettes, block/sky light, biome and height arrays are copied. Residents occupy the effective terrain view square plus two columns for meshing neighbors. The exposed `cacheRenderDistance` defaults to 16 and clamps to 2–32. Enabled terrain rendering uses the maximum of that setting and the live client distance; disabled rendering uses the live distance. Renderer-only field-read hooks cover vanilla frustum allocation/reload, Sodium manager allocation/reload, and the camera projection/fog color. GameSettings is never changed by these hooks, so integrated-server loading and remote chunk requests retain their normal distance. The maximum radius is 34 for the maximum supported terrain distance of 32, bounding the window to 4761 columns. Columns within the window do not evict each other. The active render-view entity centers scanning, retention and Sodium column handoffs, with a player fallback only while no render entity exists. Freecam movement does not move the gameplay player or change server authority. Movement and distance changes prune departing columns; live columns are excluded from disk scans and remove stale snapshots. Reads and scans use a bounded 128-task I/O queue; writes use a separate single-thread writer and a bounded 1024-coordinate coalescing queue.

The disk cache is separate from the active world save and uses `.bobby112/v1/<SHA-256 identity>/<dimension>/`. Integrated worlds use the server folder name; remote worlds use the server address and server-list name. Missing or blank server identity disables disk caching instead of reusing a shared fallback key. This identity can still collide for proxy servers with multiple worlds behind one address. `CacheRetention` prunes oldest cache-owned Anvil region files at startup below the 2 GiB budget’s 2 MiB write headroom, so reaching the saving threshold does not permanently block future sessions. New writes stop when that headroom is reached. It prunes only during LiteLoader initialization, before a world opens region handles. A symbolic link at the cache root or profile/dimension/region path disables persistent storage for safety. An inspection failure disables persistence for that session rather than treating unknown usage as available space. The limit is currently fixed, not configurable.

The cache reuses Anvil serialization but writes on Bobby's single writer rather than Minecraft's shared file-I/O queue. A shared lock serializes cache reads and writes across loader instances. Each write reads back and compares the NBT, because Minecraft's region writer can swallow an I/O failure. Failed cache-owned region handles are evicted individually so a retry can reopen them; active save handles are not cleared. Missing cache chunks are checked with `isChunkGeneratedAt` before `loadChunk`, avoiding creation of empty region files on render misses. Cached height maps must contain 256 values in the 0–256 range before Anvil decoding; malformed metadata is rejected instead of replaced by zero heights. Loaded chunks are published only after releasing the region I/O lock; holding it while waiting for the client task queue deadlocked against chunk unload. Disk work never falls back to the client thread. Queued and actively written snapshots remain readable until completion. Disk reads prefer a newer pending snapshot and copy it into the requesting world context, so a delayed write cannot restore older disk terrain. Completion cannot clear a newer replacement. Repeated saves for the same coordinate coalesce; on overflow of 1024 unique pending coordinates, the oldest save is dropped with a warning. A packaged MultiMC teleport fixture overflowed the earlier 256-entry writer queue, then completed without overflow at 1024. Orderly Minecraft shutdown waits for active and accepted queued saves to drain, preserving interruption until completion. A failed save retains its snapshot for up to three attempts, separated by 100 and 200 milliseconds; a superseded snapshot stops retrying. A terminal failure is reported by the drain and does not skip later queued work. Forced process termination cannot guarantee persistence. Longer-session queue pressure and corrupt-cache recovery remain untested.

On a render lookup, live client chunks win. A cached chunk is considered only in vanilla's render cache construction and worker neighbor check (cached centers may mesh with unknown boundary neighbors; live centers keep vanilla's neighbor requirement), or through the optional LiteOptimizer section creation, meshing and biome hooks. Missing disk chunks inside the active window are queued for background loading. Publication checks the request token, world, enabled state, current window and live provider before retaining a result. Live loads cancel pending cached work. Only world lifecycle callbacks switch cache sessions; a late unload from a previous world is ignored. Published columns and renderer add/remove transitions invalidate the column and its mesh neighbors. Live-to-cached handoff retains an existing Sodium render column when a resident snapshot covers the current render window. Cached-to-live handoff also retains that column; the normal chunk packet invalidates its cloned sections and queues fresh meshes after applying live data. Renderer-only notifications are suppressed for those handoffs, while the live provider and LiteOptimizer's listener tracking still run normally. Columns leaving the window, missing snapshots and disabled caching use normal removal. The cache is not inserted into the gameplay chunk provider.

The `bobby112.json` LiteLoader config exposes an `enabled` toggle. An initially unbound Controls entry, `Toggle Bobby terrain cache`, changes the same field in game, persists it through LiteLoader, and displays an overlay message. Key presses in menus are discarded. The mod rereads the file when its modification time changes, clears resident and pending cache state on a toggle, and reloads renderers after enable/disable. Missing/failed reads are suppressed for two seconds in a bounded 256-entry history; queue rejection releases admission without marking the chunk missing. Both lookup and scan paths can retry after the backoff. The native `Configurable` panel uses LiteLoader’s `AbstractConfigPanel` outside the Mixin package. It edits draft values for enabled state, distance and fallback, preserves them across resize callbacks, then writes the same exposed mod fields through LiteLoader when closed. The normal tick/config path applies the saved state; the panel does not mutate renderer or server state directly. The disk cache is retained when disabled.

LiteOptimizer integration covers `ChunkRenderManager.createChunkRender` before it tests section emptiness, `WorldSlice.prepare`, `ClonedChunkSection.init` and its biome lookup, plus the renderer's `onChunkAdded`/`onChunkRemoved` notifications. These mixins preserve LiteOptimizer's existing chunk listener. The packaged section-creation invocation belongs to `WorldClient`, while worker lookups belong to `World`; redirect descriptors must match these bytecode owners. Required injections use a minimum match count of one so an incompatible hook cannot silently leave holes. Runtime evidence and remaining limits are recorded in [compatibility](COMPATIBILITY.md).

## Guarantees still to prove

- Snapshot fidelity across all block states, lighting modifications and resource packs.
- Anvil reads and writes through the separate loader never touch the active world save.
- Cached terrain can be meshed with vanilla and LiteOptimizer while live chunks replace it cleanly.
- World/session changes, corrupt files, I/O failures and longer-session queue saturation recover without stale terrain or data loss.


Vanilla workers may compile cached sections and unknown empty sections inside the active cache window even when live neighbors are absent. The latter prevents unvisited gaps from retaining opaque uncompiled visibility placeholders that hide cached terrain farther away. This includes empty sections at the live frontier, which otherwise retain opaque uncompiled placeholders when a neighbor is missing. Disabled caching and positions outside the window receive no exception. This affects rendering caches only and does not publish terrain to the gameplay provider.


## Read-only fallback terrain

The opt-in `fallbackEnabled` setting defaults to false. After checking pending and recorded terrain, the bounded I/O worker can read `saves/bobby-fallback/region/` (Overworld) or `saves/bobby-fallback/DIM<id>/region/`. It uses a separate read-only region reader rather than `RegionFileCache`, so missing requests create no files and no fallback handle enters Minecraft's writable registry. Symlinked source components are rejected. Region headers, offsets, lengths, compression, coordinates, section arrays, biomes and height maps are validated; compressed payloads are bounded by their region-sector allocation and NBT decoding has a 16 MiB budget. Modern DataVersion values are rejected. Entities, tile entities and scheduled ticks are removed before and after the terrain data fixer, before invoking Anvil's terrain decoder.

Fallback publication uses the existing world/request tokens, resident bounds, render-only lookup and live priority. Fallback snapshots are never passed to the writer: unload/disconnect captures only the gameplay provider. Changing the option clears residents and pending reads, advances the generation and reloads rendering. The source is shared across worlds only when the user explicitly enables it; it is not automatic world matching.

Sparse terrain also needs a connected Sodium visibility graph. The renderer now includes empty render-only columns in the rectangle from the camera to cached columns inside the render window. These contain no gameplay chunks, and are removed when no longer needed. The rectangle is bounded to radius33 (4489 columns), including the existing meshing border. Empty columns allow the existing culler to reach isolated cached/fallback terrain without replacing its visibility algorithm.
