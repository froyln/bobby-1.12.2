# Cache and rendering architecture

## Current prototype

`ChunkProviderClientMixin` captures a detached `Chunk` when the client provider unloads a live chunk. Before Minecraft replaces or disconnects its world, `MinecraftMixin` captures remaining live chunks while the old world identity is still active. It drains previous saves, then captures and drains batches of 512 so the 1024-entry pending queue cannot overflow during this operation. Normal shutdown also passes through this world-replacement path. Section block palettes, block/sky light, biome and height arrays are copied. Residents occupy the current client view square plus two columns for meshing neighbors. The maximum radius is 34 for Minecraft's maximum supported client distance of 32, bounding the window to 4761 columns. Columns within the window do not evict each other. Movement and distance changes prune departing columns; live columns are excluded from disk scans and remove stale snapshots. Reads and scans use a bounded 128-task I/O queue; writes use a separate single-thread writer and a bounded 1024-coordinate coalescing queue.

The disk cache is separate from the active world save and uses `.bobby112/v1/<SHA-256 identity>/<dimension>/`. Integrated worlds use the server folder name; remote worlds use the server address and server-list name. Missing or blank server identity disables disk caching instead of reusing a shared fallback key. This identity can still collide for proxy servers with multiple worlds behind one address. `CacheRetention` prunes oldest cache-owned Anvil region files at startup below the 2 GiB budget’s 2 MiB write headroom, so reaching the saving threshold does not permanently block future sessions. New writes stop when that headroom is reached. It prunes only during LiteLoader initialization, before a world opens region handles. A symbolic link at the cache root or profile/dimension/region path disables persistent storage for safety. An inspection failure disables persistence for that session rather than treating unknown usage as available space. The limit is currently fixed, not configurable.

Anvil writes are submitted to Minecraft's shared `ThreadedFileIOBase` by `AnvilChunkLoader` itself. A shared lock serializes mod reads/writes across cache loader instances and Minecraft's writer callback. Missing cache chunks are checked with `isChunkGeneratedAt` before `loadChunk`, avoiding creation of empty region files on render misses. Loaded chunks are published only after releasing the region I/O lock; holding it while waiting for the client task queue deadlocked against chunk unload. Disk work never falls back to the client thread. Queued and actively written snapshots remain readable until completion. Disk reads prefer a newer pending snapshot and copy it into the requesting world context, so a delayed write cannot restore older disk terrain. Completion cannot clear a newer replacement. Repeated saves for the same coordinate coalesce; on overflow of 1024 unique pending coordinates, the oldest save is dropped with a warning. A packaged MultiMC teleport fixture overflowed the earlier 256-entry writer queue, then completed without overflow at 1024. Orderly Minecraft shutdown waits for active and accepted queued saves to drain, preserving interruption until completion. A failed save does not skip later queued work. Forced process termination cannot guarantee persistence. Longer-session queue pressure and corrupt-cache recovery remain untested.

On a render lookup, live client chunks win. A cached chunk is considered only in vanilla's render cache construction and worker neighbor check, or through the optional LiteOptimizer section creation, meshing and biome hooks. Missing disk chunks inside the active window are queued for background loading. Publication checks the request token, world, enabled state, current window and live provider before retaining a result. Live loads cancel pending cached work. Only world lifecycle callbacks switch cache sessions; a late unload from a previous world is ignored. Published columns and renderer add/remove transitions invalidate the column and its mesh neighbors. Live-to-cached handoff retains an existing Sodium render column when a resident snapshot covers the current render window. Cached-to-live handoff also retains that column; the normal chunk packet invalidates its cloned sections and queues fresh meshes after applying live data. Renderer-only notifications are suppressed for those handoffs, while the live provider and LiteOptimizer's listener tracking still run normally. Columns leaving the window, missing snapshots and disabled caching use normal removal. The cache is not inserted into the gameplay chunk provider.

The `bobby112.json` LiteLoader config exposes an `enabled` toggle. An initially unbound Controls entry, `Toggle Bobby terrain cache`, changes the same field in game, persists it through LiteLoader, and displays an overlay message. Key presses in menus are discarded. The mod rereads the file when its modification time changes, clears resident and pending cache state on a toggle, and reloads renderers after enable/disable. Missing/failed reads are suppressed for two seconds in a bounded 256-entry history; queue rejection releases admission without marking the chunk missing. Both lookup and scan paths can retry after the backoff. A native config-panel attempt failed during packaged Mixin class loading, so the current source has no panel. The disk cache is retained when disabled.

LiteOptimizer integration covers `ChunkRenderManager.createChunkRender` before it tests section emptiness, `WorldSlice.prepare`, `ClonedChunkSection.init` and its biome lookup, plus the renderer's `onChunkAdded`/`onChunkRemoved` notifications. These mixins preserve LiteOptimizer's existing chunk listener. The packaged section-creation invocation belongs to `WorldClient`, while worker lookups belong to `World`; redirect descriptors must match these bytecode owners. Required injections use a minimum match count of one so an incompatible hook cannot silently leave holes. Runtime evidence and remaining limits are recorded in [compatibility](COMPATIBILITY.md).

## Guarantees still to prove

- Snapshot fidelity across all block states, lighting modifications and resource packs.
- Anvil reads and writes through the separate loader never touch the active world save.
- Cached terrain can be meshed with vanilla and LiteOptimizer while live chunks replace it cleanly.
- World/session changes, corrupt files, I/O failures and longer-session queue saturation recover without stale terrain or data loss.
